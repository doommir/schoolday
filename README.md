# Schoolday OS · NovaPath

A generative school-day runtime for Grades 6–8. Adults set up linked learner profiles with a first name or nickname and grade. Learners then follow a single path through arrival, literacy, mathematics, movement, science, lunch, humanities, creative studio, and reflection. Solo and Squads share the lesson renderer and evidence contract. Both support persistent drafts and pause/resume. Squads offer live or asynchronous pacing.

## Run the generative workflow

The owner opens Adult workspace → Connections & review and enters an OpenAI API key and a model supporting Responses, structured outputs, and web search (default: `gpt-4.1-mini`). The connection verifies model access. Generated content is not fabricated locally when credentials are absent. API charges accrue to the connected account. The default application-wide quota is 200 generation calls per UTC day, reserved atomically before requests; the owner can change both app-wide and per-learner allowances in Launch settings. The learner default is 60 preparation calls per UTC day.

The hosted `APP_SECRET` encrypts the API key using AES-GCM. `TEACHER_EMAILS` is an explicit server-side educator allowlist; student profiles and client role switches never grant educator access. An optional server `OPENAI_API_KEY` takes precedence over the encrypted connection. Keep secrets out of Git. Runtime values are managed separately from the hosting manifest.

The current deployment is public, as requested by the owner. Adult account access and learner data still require their scoped credentials. The app uses opaque, HttpOnly student session cookies within the site, with durable server records; name alone is not authentication or a recovery credential. Resume on the same browser. Adult accounts use the stable Sites authenticated-user ID. Linked learners can be recovered on another signed-in device from the adult workspace; recovery rotates the learner capability and replaces the old browser session. Unlinked profiles remain device-bound. District SIS/SSO and a full multi-school staff/tenant administration system are not implemented. The Site access policy still determines who can reach the app; creating an app account does not grant Site access.

## Generation contract

1. Grade guidance plus prior independent check results produce one ordered five-subject day plan. On a first day this is an introductory sequence, not an inferred placement assessment.
2. Each lesson advances through persisted phases: `research → author → review_accuracy → review_pedagogy → ready`.
3. Source research uses Responses web search restricted to the authoritative domain allowlist in `lib/references.ts`. Exact citation URLs are retained with a source brief; the author must use those URLs.
4. Lessons contain six instructional stages: notice, teach, model, practice, apply, reflect; plus two independent exit questions. Content includes the reading, worked reasoning, misconception feedback, rubric, application exemplar, and optional exact numerical diagrams.
5. Zod validates shape; semantic checks validate stage order, grade/subject agreement, answer indices, diagrams, source provenance, and minimum instructional content.
6. Two separate model calls review subject accuracy and instructional/accessibility quality. Major or blocker findings cause revision. A maximum of two repairs is permitted. Persistent failures enter the educator queue and are never returned as deliverable student content.
7. An educator can inspect findings and request fresh generation. The fresh draft must pass the same gates. There is no unchecked publish override.

Each request advances one phase, with a database lease and unique lock token. API failure leaves a resumable error; previous successful phases remain. Student-facing responses omit answer keys and pre-release lesson payloads. Structural validity and model agreement do not establish factual truth or independent expert certification. The pipeline is implemented; live AI outputs have not yet been validated because no API key was available during construction.

## Evidence and adaptation

Responses, choices, self-checks, timestamps, generation reviews, and progression are stored in D1. Independent exit responses retain their first result. Practice allows supported retries. The next day planner receives grade, previous learning goals, and independent check results, not names or free-text student artifacts. Two checks are an adaptation signal, not a mastery certification. XP measures saved participation.

Squads work at the same grade and hold up to four members. Live Squads require at least two learners on the same unfinished step and advance when all members following live submit. Learners can detach to solo or asynchronous pacing without blocking everyone else. Async Squads can start with one learner; others can join later and move independently, including after the starter finishes. Peers' learning responses become visible after the learner contributes; independent check answers stay private. Application/reflection threads and replies remain available after completion.

A member’s compatible subject block adopts the shared lesson; evidence and completion remain attached to their own day. Different started work or drafts cannot be overwritten. Changing modes preserves progress. Drafts use optimistic versions to reject competing stale saves, and saved work can be restored after closing the browser. Adult-linked profiles support recovery on another signed-in device. New student responses and finished blocks advance directly into the next activity, with a primary Continue action returning to unfinished saved work.

## Continuing learning and help

My work now includes subject-level participation and first-check counts, ideas to revisit, and the most recent 60 saved days. Historical lessons and original responses can be inspected read-only, including numerical diagrams and citations. First independent answers remain immutable. The XP display counts all saved evidence across days; participation, correct first responses and mastery are not interchangeable. The app does not certify mastery or full-year standards coverage.

Learners can save larger text, a quieter focus view, reduced animation, slower read-aloud, and chunked instruction preferences. Only the structured instruction preference enters future generation; it does not change existing lessons, grade-level objectives, or imply a diagnosis. Read-aloud uses the browser's available speech service. The page warns before closing when an edited draft has not yet been confirmed saved; offline learning/storage is not implemented.

Ask for help saves a question against the activity and step. An adult must first link the learner or an allowlisted educator must be assigned. The Questions tab shows only that adult's linked learners or the educator's currently assigned learners. Replies appear inside the learner app on opening/refreshing Questions & help. There are no emails, texts, push notifications, emergency monitoring, or response-time promises. A reply is written once, cannot be silently overwritten, and can be marked read by the learner; follow-up questions create separate records. Help text and adult replies are excluded from AI generation inputs. Retention follows the existing pilot limitations and still requires an adopted operational policy.

## California school operations

The educator space adds a scoped long-term traditional independent study record workflow for grades 6–8. School authorization and legal compliance are not conferred by the app. Operational enrollment and official attendance remain disabled, even when all reference fields are filled.

- School configuration: school of record, district/charter, CDS reference, actual instructional calendar, policy/contract/support/attendance references and grade 6–8 sequences. The annual planning reference is 54,000 minutes and 175 charter / 180 district days; calendar entries and timers are not verified offerings or attendance.
- Learner records reference an existing completed agreement, required signature verification, credential verification and assigned authorized teacher. No signature is executed by ticking a checkbox.
- Human instruction sessions record scheduled, participated, nonparticipatory and cancelled states. The middle school rule is daily live interaction and at least weekly teacher-led synchronous opportunities. Peer Squads and AI do not substitute for these. Nonparticipation is not converted to absence/truancy.
- Only the assigned educator can record sessions, personally judge work time value, or record support actions. Reviews store an immutable copy and hash of the lesson and work at review time; later reviews supersede prior judgments while retaining history. Routine breaks are excluded. No ADA is generated.
- Records export as JSON with authors, timestamps and source references. The export supports review; it is not a certified transcript or attendance report. Updates append history; the current app exposes no school-record delete endpoint. Retention/deletion implementation requires the school’s adopted policy and applicable record rules.
- Required pre-operation work includes school authorization, school-grade identity assurance, staff/tenant role administration, vendor privacy contracts, accessibility review, mandated supports/assessments, assignment/deadline records and integration with the school’s approved attendance system. No school operating approval is implied by an authorized app account.

## Customer entry, device access, and launch

The `/try` route is a complete original, fixed sample lesson for each grade. It teaches unit rates (6), scale lengths (7), or linear rate/initial value (8), with a worked model, practice feedback, application and independent check. No API key, learner account, payment or server-stored student response is required. It is explicitly a sample, not generated content or a complete course.

Adult setup offers a six-digit PIN and a one-time displayed recovery code. PINs use PBKDF2-SHA256 with a per-account salt and 100,000 iterations; recovery codes are hashed. Adult unlock cookies are encrypted, bound to the authenticated Sites user and current PIN hash, and expire after 30 minutes. Five failed attempts trigger a 15-minute delay. Opening a learner day clears the adult unlock; server-side account, operator and educator checks enforce the lock. Existing pilot accounts without a PIN remain compatible, and can add one in Help; new live-plan accounts must set a PIN. This is an additional adult-control gate, not identity or age verification.

The adult can issue a one-use 64-bit learner device code, stored only as a hash and valid for ten minutes. Redemption rotates the existing learner capability and removes adult unlock access in the receiving browser. It moves the learner's active session; it is not multi-device concurrent sign-in. Device codes cannot grant Site audience access. In private publishing the receiving browser still needs Site access; public customer rollout must deliberately configure the intended audience.

While a learner keeps My day or a lesson open, the app advances preparation of the next subject through the existing reviewed pipeline. Only one background phase runs at a time. Manual opening waits for an in-flight phase for the same lesson; failures pause automatic retries for that page session instead of looping. There is no cron/queue processing while all app windows are closed. Held content is skipped by the primary Continue action so another activity remains reachable. A held lesson with submitted work or drafts cannot be reset over those records; a human must arrange a separately preserved replacement.

Launch settings control live checkout and daily allowances. Live sales default closed until an AI connection, verified live prices, policy/support URLs, a signing secret, and receipt of a live signed Stripe event are present. These are connection checks, not comprehensive operating approval. The connection automatically registers the required Stripe event types, including customer.created for a no-charge delivery check before checkout opens. Owner-provided live keys, actual merchant pricing/policies, public audience configuration, real generation quality validation, provider test purchases and child-data arrangements remain required. No live provider calls or real charges were made during construction. Sample lessons and mocked provider tests cannot establish customer satisfaction, complete standards coverage, or legal school compliance.

Stripe implementation references: [signed events](https://docs.stripe.com/webhooks), [event endpoint creation](https://docs.stripe.com/api/webhook_endpoints/create), [customer portal configuration](https://docs.stripe.com/api/customer_portal/configurations/create).

## Standards and generation reliability (V8)
New day plans select exact identifiers from `data/standards-catalog.json`, imported from the California Department of Education's content standards search on 2026-09-08. Grade and subject mismatches or invented IDs fail before activities are created. The catalog includes mathematics, grade-specific ELA, HSS substandards, and all 59 middle-school science performance-expectation identifiers, mapped to California's preferred integrated sequence; engineering expectations recur across grades. Studio uses writing standards for project communication. This is a standards inventory, not a validated complete course sequence or coverage of all California school subjects. The catalog stores identifiers, domains and official links; it does not redistribute the standards' full text. Import provenance: `scripts/import-standards.py`, grade maps from the three CDE integrated-course PDFs linked in each science row. URLs and mapping were checked during implementation.

During research, the server retrieves the exact official standard page from its catalog URL, captures its expectation and boundaries, and retains a versioned, hashed audit snapshot. It caches that snapshot for the current curriculum version. A first retrieval failure stops generation; cached snapshots and prepared lessons remain available. Changes to the adopted standards require a new catalog version and reviewed cache refresh. External references remain untrusted data. Generated lessons identify the assigned standard and explain how tasks address it. Source, author, accuracy, pedagogy, and standards-alignment phases must complete. The accuracy reviewer records three independently reasoned answer choices; disagreement with the authored keys fails the review. All three named reviewers must pass without major/blocking findings. Deterministic checks also cover valid choice indices, distinct questions, diagrams, source provenance and planned duration. At most two repairs; four consecutive operational failures hold a phase for an educator. These controls reduce failures; they cannot establish that model judgments or every factual claim are correct.

New released content gets a fingerprint over the exact lesson and standard snapshot. Delivery, answers, and Squads check it and the three review records. A report revokes pending generation and holds identical copied lessons. Stale generation cannot overwrite a newer result or a hold. Planner transactions are lease-token guarded, so a late response cannot append duplicate blocks or replace the current plan. Failed phases retain prior work, require a one-minute retry delay and consume bounded usage. First independent responses use atomic conflict-ignore writes.

Unfinished legacy pilot activities without assigned standards are migrated to held status. Educators choose a standard and either restart an unused activity or create a replacement that keeps all earlier evidence/drafts attached to the old activity. Replacements occupy the same current-day slot; superseded blocks no longer prevent day completion. Completed legacy records remain readable and explicitly unverified; they cannot seed new Squads. Educators can inspect held drafts and answer keys. Progress exposes standards assigned and standards with completed lessons, explicitly separate from mastery. These changes do not certify effectiveness, full-year coverage, legal school status, or independent-study attendance.

Verification includes synthetic provider faults, official-source outage, stale planner/generator responses, concurrent first answers, blocked release on reviewer disagreement, modified payloads, and preserved-work replacement. Real model generations across grades/subjects, expert review of a representative lesson sample, accessibility/browser testing, and evidence of student learning are still needed before claiming instructional effectiveness. No real provider key was supplied to this audit, and synthetic reviews are not curriculum validation.
